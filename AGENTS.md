# nerdesign – the Nerdesign design system

Personal design system for everything HTML made for Helgerød gård (Jeløya, Moss): printable documents
(circuit overviews, rental prospectus, A4 handouts) and smart-home dashboards. One identity, light + dark,
WCAG 2.2 AA. Owner: Erlend. **This repo is public** – read «Public hygiene» below before adding anything.

Until 8 Oct 2026 the source lived in a private repo (`nerdegutt/nerdesign-private`, archived) and this repo only
received releases. Its history and checkpoint log stay there.

The website is the app `nerdesign` in Dokploy on the family home server (project `erlend`, environment

## Conventions (non-negotiable)

- **English in all source code** – tokens, class names, file names, JS, comments, commits. **Norwegian in
  everything a reader sees** – UI text, pattern book content, examples, `lang="nb"`. Keep Norwegian typography
  (`·`, `–`, æøå).
- The system is called **Nerdesign**. Prefix everything `nd-` (`--nd-accent`, `.nd-kicker`, `ndEchartsTheme`).
  Themes are just «lyst» and «mørkt» – no theme names in public text.
- **Edit `src/`, never `dist/`.** `dist/` is generated by `npm run build` and committed so consumers can copy
  without tooling.
- Components use semantic tokens only (`--nd-text`), never primitives (`--nd-earth-900`).
- `src/tokens/*.dark.css` contain declarations only; the build wraps them under both dark selectors. Never
  hand-write a dark block.
- `src/print.css` is always last in the build.
- No external dependencies in `dist/` – no CDN, no Google Fonts. Fonts are self-hosted (OFL) in `fonts/`, shipped
  via `dist/nd-fonts.css` separately from `nd.css`.
- CSS-first: components are classes + documented HTML patterns, plus small vanilla ES-module helpers. No
  framework.
- Fonts must be OFL-licensed with the licence file next to them.

## Public hygiene

Everything in this repo and on the website is public. Use synthetic data and never mention, link to or include
material from the private projects that use the system; the website talks about «dokumenter» and «dashboards»
generically. Photos of the farm are allowed in examples (downsized to ≤1400 px), but no addresses, names or
contact details. Notes about a consumer project belong in that project's own repo, not here.

## Commands

```bash
npm run build        # src → dist (banner, dark duplication)
npm run contrast     # WCAG contrast for every pair in src/tokens/pairs.json, both themes
npm run palette      # dataviz palette validator for series/sequential/diverging, both themes
npm test             # Playwright: screenshots light/dark, axe-core, forced-colors, reduced-motion
npm run test:print   # PDF of examples/*, asserts page counts
tools/copy-to.sh ../my-project --with-fonts [--release vX.Y.Z]   # vendor into a project
tools/publish.sh vX.Y.Z   # bump, build, test, commit + tag, deploy (root + /vX.Y.Z/), GitHub Release
tools/deploy.sh      # build the site into nettsted/, commit, push → https://nerdesign.offline.no/
tools/dev-server.mjs # copy into a project for local preview (serves public/ or the root, answers /api/config)
docker build -t nerdesign . && docker run --rm -p 3000:3000 nerdesign   # the website as it runs on the server
```

## Layout of the repo

- `src/tokens/` primitives → semantic → data, `pairs.json` for contrast checks
- `src/base/` reset, typography, a11y · `src/layout.css` · `src/components/{document,dashboard}/` · `src/print.css`
- `src/nd-echarts.js` ECharts theme/option helpers reading tokens at runtime · `src/nd-theme.js` toggle
- `site-src/` website page fragments → `site/` (ignored build output) → `nettsted/` (published, committed)
- `examples/` synthetic-data examples used by print and axe tests
- `design/` design artboards (`*.dc.html`, `canvas.json`) · `docs/` agent skill copy and a snippet for consumers
- `tools/` build, wcag math, contrast, palette, copy-to, publish, deploy · `test/` Playwright specs

## Releases and vendoring

Semver; `package.json` version is the truth and ends up in the banner of every dist file
(`/* Nerdesign v1.2.0 – … */`). A release is a git tag + GitHub Release with `dist/` attached. Consumers pin a
release and copy with `tools/copy-to.sh`; they never edit `nd/` locally. Optional pinned URL for non-print use:
`https://cdn.jsdelivr.net/gh/nerdegutt/nerdesign@vX.Y.Z/dist/nd.css`.

## Versioning on the website

`tools/publish.sh vX.Y.Z` releases on request. The website root is always the latest; every release is also
deployed as a frozen snapshot at `/vX.Y.Z/`. `versjoner.html` is generated from `CHANGELOG.md` (write release
notes there and nowhere else). Snapshots show a quiet banner pointing to the latest version. There is no dev
concept: `tools/deploy.sh` puts the current state straight on the root.
